## 二、Unity 编辑器基本操作

### 需要熟悉的窗口

- **Scene 窗口**：编辑场景，摆放对象
- **Game 窗口**：预览游戏运行效果

- 在 Scene 窗口按住右键旋转视角，滚轮缩放，中键平移

## 四、GameObject 和 Component

### 这是 Unity 最核心的概念

Unity 中所有东西都是 **GameObject**（游戏对象）。

每个 GameObject 由多个 **Component**（组件）组成。

举个例子：一个 Cube：

- Transform：决定位置、旋转、缩放
- Mesh Filter：定义形状
- Mesh Renderer：负责渲染可见
- Box Collider：负责碰撞

组件决定了这个对象"是什么"和"能做什么"。

### 常见的组件

| 组件 | 作用 |
|------|------|
| Transform | 位置、旋转、缩放 |
| MeshRenderer | 显示模型 |
| Collider | 碰撞体积 |
| Rigidbody | 物理模拟 |
| Light | 光源 |
| Camera | 摄像机 |
| AudioSource | 播放声音 |
| Animator | 播放动画 |

### 在代码里获取组件

```csharp
using UnityEngine;

public class Player : MonoBehaviour
{
    private Transform myTransform;
    private Rigidbody myRigidbody;

    private void Awake()
    {
        myTransform = GetComponent<Transform>();
        myRigidbody = GetComponent<Rigidbody>();
    }
}
```

### 练习要求

- 创建一个 Cube
- 在 Inspector 里查看它有哪些组件
- 给 Cube 添加一个 Rigidbody
- 运行游戏，看 Cube 会不会受重力下落
- 写一个脚本，在 Awake 里获取自己的 Transform

## 五、MonoBehaviour 生命周期

所有 Unity 脚本都继承 `MonoBehaviour`，它有一系列自动调用的方法。

### 最常用的生命周期方法

```csharp
using UnityEngine;

public class LifecycleDemo : MonoBehaviour
{
    // 最早调用，只调用一次
    private void Awake()
    {
        Debug.Log("Awake：适合初始化自身组件");
    }

    // Awake 之后调用，只调用一次
    private void Start()
    {
        Debug.Log("Start：适合初始化需要依赖其他对象的逻辑");
    }

    // 每帧调用一次
    private void Update()
    {
        Debug.Log("Update：每帧都执行，适合输入检测");
    }

    // 固定时间间隔调用，适合物理相关
    private void FixedUpdate()
    {
        Debug.Log("FixedUpdate：适合物理计算");
    }

    // 每帧最后调用
    private void LateUpdate()
    {
        Debug.Log("LateUpdate：适合摄像机跟随");
    }

    // 对象启用时
    private void OnEnable()
    {
        Debug.Log("OnEnable：对象被激活时调用");
    }

    // 对象禁用时
    private void OnDisable()
    {
        Debug.Log("OnDisable：对象被禁用时调用");
    }

    // 对象销毁时
    private void OnDestroy()
    {
        Debug.Log("OnDestroy：对象被销毁时调用");
    }
}
```

### 关键区别

- `Awake`：自身初始化
- `Start`：可以安全引用外部对象
- `Update`：每帧执行，大部分逻辑放这里
- `FixedUpdate`：物理计算放这里
- 不要把所有逻辑都塞进 `Update`

### 练习要求

- 观察 Console 里的输出顺序
- 把一个对象的脚本 `enabled = false`，观察 `OnDisable` 和 `OnEnable`
- 销毁一个对象，观察 `OnDestroy`

## 六、Transform：让东西动起来

Transform 决定对象在场景中的位置、旋转和缩放。

### 基本操作

```csharp
using UnityEngine;

public class Mover : MonoBehaviour
{
    public float speed = 3f;

    private void Update()
    {
        // 向前移动
        transform.Translate(Vector3.forward * speed * Time.deltaTime);

        // 绕 Y 轴旋转
        transform.Rotate(Vector3.up * 90f * Time.deltaTime);
    }
}
```

### 为什么需要 Time.deltaTime

- `Update` 每一帧调用一次
- 不同电脑的帧率不一样
- `Time.deltaTime` = 上一帧到这一帧的时间差
- 乘以 `Time.deltaTime` 后，移动速度不受帧率影响

```csharp
// 不用 deltaTime：帧率越高移动越快，帧率越低移动越慢
transform.Translate(Vector3.forward * speed);

// 用 deltaTime：不同帧率下每秒移动距离一致
transform.Translate(Vector3.forward * speed * Time.deltaTime);
```

### 常用属性和方法

```csharp
// 获取位置
Vector3 pos = transform.position;

// 设置位置
transform.position = new Vector3(1, 2, 3);

// 获取前方方向
Vector3 forward = transform.forward;

// 看向某个目标
transform.LookAt(target.position);

// 获取子对象
Transform child = transform.GetChild(0);

// 获取父对象
Transform parent = transform.parent;
```

- 加入旋转
- 分别测试加和不加 `Time.deltaTime` 的效果
- 让一个对象始终面向另一个对象

public class PlayerInput : MonoBehaviour

## 八、物理与碰撞

Unity 内置了物理引擎，可以检测碰撞和模拟重力。

### Rigidbody（刚体）

让对象受物理引擎控制：

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody))]
public class PhysicsMover : MonoBehaviour
{
    private Rigidbody rb;

    private void Awake()
    {
        rb = GetComponent<Rigidbody>();
    }

    private void FixedUpdate()
    {
        float horizontal = Input.GetAxis("Horizontal");
        float vertical = Input.GetAxis("Vertical");

        Vector3 move = new Vector3(horizontal, 0, vertical) * 5f;

        // 通过 Rigidbody 移动（不直接改 transform.position）
        rb.velocity = new Vector3(move.x, rb.velocity.y, move.z);
    }
}
```

### Collider（碰撞器）

碰撞器定义对象的物理边界。常见类型：

- Box Collider（盒子）
- Sphere Collider（球体）
- Capsule Collider（胶囊体）
- Mesh Collider（网格）

### 碰撞检测方法

```csharp
// 碰撞开始
private void OnCollisionEnter(Collision collision)
{
    Debug.Log($"撞到了 {collision.gameObject.name}");
}

// 持续碰撞
private void OnCollisionStay(Collision collision)
{
    Debug.Log("正在碰撞中");
}

// 碰撞结束
private void OnCollisionExit(Collision collision)
{
    Debug.Log("碰撞结束");
}
```

### 触发器（Trigger）

勾选 Collider 的 `Is Trigger` 后，变成触发器：

```csharp
// 进入触发器
private void OnTriggerEnter(Collider other)
{
    Debug.Log($"{other.name} 进入了触发区域");
}

// 停留在触发器中
private void OnTriggerStay(Collider other)
{
    Debug.Log($"{other.name} 停留在触发区域");
}

// 离开触发器
private void OnTriggerExit(Collider other)
{
    Debug.Log($"{other.name} 离开了触发区域");
}
```

### 碰撞需要什么条件

| 碰撞类型 | 发送方 | 接收方 |
|----------|--------|--------|
| Collision | Rigidbody + Collider | Collider |
| Trigger | Rigidbody + Collider(IsTrigger) | Collider |
| Trigger | Collider(IsTrigger) | Rigidbody + Collider |

至少要有一方有 Rigidbody，碰撞检测才能正常工作。

- 给球加 Rigidbody 和 Sphere Collider
- 运行看球受重力下落
- 给球加一个脚本，用 WASD 移动球的物理体
- 做一个收集物：Sphere Collider 设为 Trigger，碰撞到球时销毁收集物

## 十、预制体（Prefab）

预制体是把一个 GameObject 保存为模板，可以重复使用。

### 为什么需要预制体

没有预制体时：
- 同样的东西要手动复制很多份
- 修改一个后还要手动改其他的
- 容易漏改，容易不一致

有预制体后：
- 修改预制体，所有实例自动同步
- 通过代码可以动态生成

### 创建预制体

在 Hierarchy 里把配置好的 GameObject 拖到 Project 窗口中即可。

### 代码里生成预制体

```csharp
using UnityEngine;

public class Spawner : MonoBehaviour
{
    [SerializeField] private GameObject enemyPrefab;
    [SerializeField] private Transform spawnPoint;

    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
        {
            Instantiate(enemyPrefab, spawnPoint.position, spawnPoint.rotation);
        }
    }
}
```

### 练习要求

- 建一个包含 Cube + Rigidbody 的对象
- 做成预制体
- 写一个脚本，按空格键在随机位置生成预制体
- 拖一个预制体到场景里，修改预制体后看场景里是否跟着变

## 十一、协程（Coroutine）

协程可以让代码"暂停一段时间再继续"，不需要用计时器变量。

### 为什么需要协程

```csharp
// 不用协程：需要计时器变量
private float timer;
private void Update()
{
    timer += Time.deltaTime;
    if (timer >= 2f)
    {
        Debug.Log("2 秒到了");
        timer = 0f;
    }
}
```

```csharp
// 用协程：更直观
private void Start()
{
    StartCoroutine(DelayedLog());
}

private IEnumerator DelayedLog()
{
    Debug.Log("开始等待");
    yield return new WaitForSeconds(2f);
    Debug.Log("2 秒到了");
}
```

### 协程常见用法

```csharp
// 等待一帧
yield return null;

// 等待固定更新
yield return new WaitForFixedUpdate();

// 等待秒数
yield return new WaitForSeconds(1.5f);

// 等待直到条件满足
yield return new WaitUntil(() => score >= 100);

// 等待另一个协程结束
yield return StartCoroutine(AnotherCoroutine());

// 等待场景加载结束
yield return new WaitForEndOfFrame();
```

### 启动和停止协程

```csharp
private Coroutine myCoroutine;

private void Start()
{
    myCoroutine = StartCoroutine(LoopAction());
}

private void StopMyCoroutine()
{
    if (myCoroutine != null)
    {
        StopCoroutine(myCoroutine);
    }
}

private IEnumerator LoopAction()
{
    while (true)
    {
        Debug.Log("每秒执行一次");
        yield return new WaitForSeconds(1f);
    }
}
```

- 写一个循环协程，每秒生成一个 Cube
- 写一个按钮，点击后停止生成
- 用协程做一个简单的倒计时

## 十三、调试基础

写代码一定会出 Bug，要学会自己找问题。

### Debug.Log

```csharp
Debug.Log("普通日志");
Debug.LogWarning("警告日志");
Debug.LogError("错误日志");
```

### 常见错误类型

| 错误信息关键字 | 常见原因 |
|---------------|---------|
| NullReferenceException | 访问了一个空引用，忘记赋值或在赋值之前就用了 |
| MissingComponentException | 缺少必需的组件 |
| IndexOutOfRangeException | 数组或列表索引越界 |
| ArgumentException | 方法参数不合法 |
| StackOverflowException | 无限递归 |

### 查找问题的步骤

1. 看 Console 里的错误信息，找到报错的文件和行号
2. 双击错误信息，跳到对应代码
3. 检查报错那行引用的对象是不是 null
4. 加 `Debug.Log` 打印关键变量，确认数据和预期是否一致
5. 修好后删掉多余的 Debug

### 使用 Inspector 调试

- 把脚本里的 `private` 改成 `[SerializeField]`，就可以在 Inspector 里看到值
- 运行游戏时，Inspector 里的值会实时变化

```csharp
using UnityEngine;

public class DebugExample : MonoBehaviour
{
    // 在 Inspector 里可以直接看到和修改这个值
    [SerializeField] private int health = 100;
    [SerializeField] private float speed = 5f;
}
```

### 练习要求

- 故意写一个空引用错误，看 Console 报什么
- 用 Debug.Log 打印变量，确认运行逻辑正确
- 练到能根据错误信息定位到具体代码位置

## 十七、最重要的提醒

第一阶段最容易犯的错不是"学不会"，而是：

- "教程全看完再动手" → 看一堆视频，一行代码没写
- "这个太简单了不想做" → 基础没练够，后面卡得更久
- "啥都想学" → 同时开十几个教程，一个都没做完
- "报错了就删掉重来" → 不学会 Debug，后面怎么修

正确的方式是：

> 看一点，写一点，跑通一点。写出来的代码再简单，也比脑子里想一千行有用。

不要一开始就追求"写得优雅"。
第一阶段的代码乱一点没关系，先练到能跑通、能改、能自己发现错误。

第一阶段真正要练的是：

> 能把自己的想法，变成能在 Unity 里跑起来的东西。

当你不再害怕打开 Unity，不再害怕写脚本，不再害怕报错，就说明第一阶段的底子稳了。

往后看第二阶段的设计模式和第三阶段的工程架构，才能真正用起来，而不是"知道名字，不知道怎么用"。
