# C++ 八股与计算机组成原理八股

> 面试冲刺自用整理：C++ 高频八股（指针/引用、对象模型、内存管理、STL、移动语义等，与 C# 对照方便迁移）与计算机组成原理高频八股（Cache、虚拟内存、补码与浮点、流水线、字节序等）。适合游戏客户端方向笔试面试复习，文末附两套自测表。

## 一、C++ 八股

### 1.1 指针与引用

| 对比项 | 指针 | 引用 |
| --- | --- | --- |
| 本质 | 保存地址的变量，本身占内存 | 变量的别名，不占独立内存（编译后等同原变量） |
| 是否可空 | 可为 `nullptr` | 必须初始化且不可为空 |
| 是否可改绑 | 可以指向别的对象 | 一旦绑定不可改绑 |
| 是否可重新赋值语义 | 赋值改变指向 | 赋值改变所指对象的值 |
| 运算 | 支持指针算术（++/--/偏移） | 不支持 |
| 多级 | 有二级指针 | 无引用之引用 |

**要点**
- 函数传参：小对象传值、结构大对象传 `const T&`、需要改指向时传指针、需要改对象内容时传引用或指针均可。
- 返回引用时禁止返回局部变量引用（悬垂）。

```cpp
int a = 1, b = 2;
int* p = &a;      // p 指向 a
p = &b;           // 改指向：p 现在指向 b
int& r = a;       // r 是 a 的别名
r = b;            // 等价 a = b（把 b 的值赋给 a），r 仍绑定 a
```

### 1.2 const / static / 内存布局

**const 用法总结**

| 写法 | 含义 |
| --- | --- |
| `const int* p` / `int const* p` | 指向常量的指针：不能通过 p 修改指向内容，p 可改 |
| `int* const p` | 常量指针：p 本身不可改，指向内容可改 |
| `const int& r` | 常引用：不能通过 r 修改 |
| `const` 成员函数 | 不修改成员（`this` 为 const），可被 const 对象调用 |
| `mutable` 成员 | 在 const 函数中仍可修改（如缓存/锁） |

**static 四种场景**

| 场景 | 作用 | 生命周期/作用域 |
| --- | --- | --- |
| 局部 static 变量 | 只初始化一次，保留上次值 | 程序启动构造、结束时析构；仅函数内可见 |
| 全局/命名空间 static | 内部链接，避免跨编译单元符号冲突 | 整个程序 |
| 类内 static 成员变量 | 所有对象共享一份 | 需在类外定义 |
| 类内 static 成员函数 | 无 this，只能访问静态成员 | 不依赖对象 |

**C++ 内存布局（由低到高）**
1. 代码段（.text）：机器指令，只读
2. 数据段：.data（已初始化全局/静态）、.bss（未初始化全局/静态，不占文件空间）
3. 堆：`new`/`malloc`，向高地址增长，手动管理
4. 栈：局部变量/函数调用帧，向低地址增长，自动管理
5. 内核区（高地址）

**经典问答**
- 栈区默认大小（Linux 8MB，可 ulimit 改），堆可到物理内存/虚拟内存上限。
- 栈溢出常见：递归过深、超大局部数组；堆溢出：越界/泄漏。

### 1.3 结构体对齐

**规则**
1. 成员偏移是「自身对齐值」的整数倍
2. 结构体总大小是「最大对齐值」的整数倍
3. 可通过 `#pragma pack(n)` 或 `alignas` 调整

```cpp
struct A {          // 默认 8 字节对齐（64 位指针/最大 double）
    char  c;   // 偏移 0
    int   i;   // 偏移 4（padding 3）
    char  d;   // 偏移 8
    // 尾部 padding 至 sizeof=16
};
static_assert(sizeof(A) == 16);
// 调整顺序可省空间：int、char、char -> 8 字节
```

**为什么要对齐**：CPU 按字读取内存，未对齐可能两次访存或直接异常；游戏网络协议/序列化常用 `#pragma pack(1)` 紧凑打包，但牺牲访问性能。

### 1.4 面向对象三大特性

- **封装**：访问控制 public/protected/private + 友元突破。
- **继承**：is-a 关系；对象切片（基类对象接收派生类只保留基类部分）。
- **多态**：运行时通过虚函数表；编译时通过函数重载/模板。

**虚函数与虚表原理（重点）**
- 含虚函数的类有一个隐藏的 `vptr` 指向 `vtable`（类共享一张，虚函数地址数组）。
- 对象内存首位是 vptr（多继承则多个）。
- 构造顺序决定 vptr 指向：基类构造期间调用虚函数是基类版本（不要在构造/析构中调用虚函数）。
- `virtual` 有运行时开销（间接跳转 + 无法内联），高频热路径可用 CRTP/模板替代。
- 析构函数一般声明为 `virtual`（基类指针 delete 派生类时防止只析构基类部分造成泄漏）。
- 纯虚函数使类抽象不可实例化；C++11 后 `override`/`final` 显式标记。

**构造/析构执行顺序**
- 构造：先基类 → 再成员（按声明顺序）→ 最后自身构造体
- 析构：严格相反：自身 → 成员 → 基类

**拷贝构造 / 拷贝赋值 / 移动**
- 深浅拷贝：默认是逐字节浅拷贝，含指针时必须深拷贝（写拷贝构造 + 拷贝赋值 + 析构三法则 Rule of Three）。
- 移动语义（C++11）：`std::move` 把左值转右值，触发移动构造/赋值（转移资源所有权而非复制）。
- 被移动后的对象处于「合法但未指定」状态，通常应可析构、可重新赋值。

```cpp
class Buffer {
    int* data; size_t n;
public:
    Buffer(const Buffer& o) {           // 深拷贝
        n = o.n; data = new int[n];
        std::copy(o.data, o.data + n, data);
    }
    Buffer(Buffer&& o) noexcept          // 移动：偷资源
        : data(o.data), n(o.n) { o.data = nullptr; o.n = 0; }
    ~Buffer() { delete[] data; }
};
```

### 1.5 内存管理

**new/delete vs malloc/free**

| 对比项 | malloc/free | new/delete |
| --- | --- | --- |
| 本质 | C 库函数 | C++ 运算符（表达式） |
| 是否调构造/析构 | 不调用 | 调用构造/析构 |
| 返回类型 | void* 需强转 | 类型安全 |
| 失败行为 | 返回 NULL | 抛 `bad_alloc` |
| 能否重载 | 否 | 可（operator new） |

**智能指针（C++11，面试必考）**

| 类型 | 所有权 | 说明 |
| --- | --- | --- |
| `unique_ptr` | 独占 | 不可拷贝，可 move；开销同裸指针；数组特化 `unique_ptr<T[]>` |
| `shared_ptr` | 共享 | 引用计数（控制块），拷贝计数+1，析构-1 归零释放；线程安全的是计数本身，指向对象不保证 |
| `weak_ptr` | 弱引用 | 不增加计数；`lock()` 升级为 shared_ptr 判空，用于打破循环引用 |

- **循环引用**：A 持 shared_ptr<B>，B 持 shared_ptr<A>，计数永不归零 → 用 weak_ptr 打断。
- enable_shared_from_this：在成员函数内安全拿自己的 shared_ptr。

**RAII**：资源获取即初始化——构造时获取、析构时释放，栈对象离开作用域必然析构，异常安全。智能指针、锁守卫（lock_guard）、文件流都是 RAII。

### 1.6 C++11/14/17 高频新特性

- **auto**：类型推导；**decltype**：不求值取类型。
- **范围 for**、**nullptr**、**constexpr**（编译期求值）、**enum class**（强类型枚举）。
- **lambda**：`[捕获](参数) -> 返回 { }`；捕获 `[=]`/`[&]`/`[this]`/初始化捕获 `[x = std::move(v)]`。
- **移动语义 + 右值引用**：`T&&` 绑定右值；`std::move` 转右值、`std::forward` 完美转发（模板 `T&&` 时保持值类别）。
- **可变参数模板**、**tuple**、**结构化绑定（17）**：`auto [a, b] = pair;`
- **if/switch 初始化语句（17）**、`std::optional`/`std::variant`/`std::any`、`string_view`（零拷贝只读视图）、`std::filesystem`。
- **智能指针线程安全**：shared_ptr 控制块原子操作。

### 1.7 STL 高频考点

**vector**
- 动态数组，连续内存；倍增扩容（常见 ×1.5/×2），扩容 = 新分配 + 搬移/拷贝 + 释放旧。
- `reserve` 预分配避免频繁扩容；`resize` 改变 size 并构造。
- **迭代器失效**：插入/删除导致 reallocation 时全部失效；中间删除使后续迭代器失效；`erase` 返回下一个有效迭代器。
- 已知大小场景可用 `vector::reserve`；频繁头部插入用 deque/list。

**map vs unordered_map**

| 对比项 | map | unordered_map |
| --- | --- | --- |
| 底层 | 红黑树（有序） | 哈希表（桶+链表/开地址） |
| 查找/插入复杂度 | O(log n) | 平均 O(1)，最坏 O(n) |
| 有序遍历 | 支持（按 key） | 不支持 |
| 适用 | 需要有序/区间查询 | 海量等值查询 |

- 红黑树特性：近似平衡 BST、根黑、红节点子必黑、最长路径 ≤ 2×最短路径，保证 O(log n)。
- 哈希冲突解决：链地址法（开放寻址也问过）；自定义 key 需提供 hash 与 `operator==`。

**其他**
- list：双向链表，O(1) 插入删除，缓存不友好（每个节点分散）。
- deque：双端队列，分段连续，头尾 O(1)。
- string：COW（旧）/SSO（小字符串优化）要知道概念；`std::string_view` 避免拷贝。

### 1.8 类型转换

| 转换 | 用途 | 危险 |
| --- | --- | --- |
| `static_cast` | 编译期相关类型转换（int→float、上行、void*→T*） | 不做运行期检查 |
| `dynamic_cast` | 多态下行/交叉转换，运行时检查（需 RTTI） | 失败返回 nullptr / 抛 bad_cast；有开销 |
| `const_cast` | 去掉 const | 对真正 const 对象修改是 UB |
| `reinterpret_cast` | 位级重解释（如 int↔指针） | 最危险，慎用 |

C 风格 `(T)x` 等价于上述的组合尝试，面试说尽量用 C++ 风格。

### 1.9 编译链接过程

1. **预处理**：宏展开、头文件包含、条件编译 → .i
2. **编译**：词法/语法/语义分析 + 优化 → 汇编 .s
3. **汇编**：汇编器转机器码 → 目标文件 .o（含符号表、未解析引用）
4. **链接**：符号解析 + 重定位，合并段 → 可执行文件；静态库 `.a` 参与链接，动态库 `.so`/`.dll` 运行时加载

**常见问答**
- 声明 vs 定义：声明可多次，定义只能一次；ODR（单一定义规则）。
- 头文件防重复包含：`#pragma once` vs 宏守卫。
- 未定义符号：编译期报（未声明）或链接期报（未定义实现）。
- 虚函数表在编译期生成、由链接保证唯一。

**inline vs 宏**
- 宏：预处理期纯文本替换，无类型检查，有副作用风险（`#define SQUARE(x) x*x`）。
- inline：编译期建议内联，有类型检查/作用域，多次定义 OK（弱符号）；是否内联由编译器决定，递归/虚函数通常不内联。

### 1.10 多线程与并发

- **创建**：`std::thread`、`std::async`；join 等待 / detach 后台（慎用，生命周期难控）。
- **同步原语**：`mutex`（lock_guard/unique_lock RAII 锁）、`condition_variable`（需配合 unique_lock + 谓词防止虚假唤醒）、`atomic`（无锁基本类型）。
- **死锁四条件**：互斥、持有并等待、不可剥夺、循环等待；解法：锁顺序一致、`std::lock` 一次锁多个、超时锁 try_lock。
- 游戏客户端：主线程渲染 + 工作线程加载/寻路/物理；注意把数据只读或按线程分区，避免锁竞争拖垮主线程。
- **数据竞争/UB**：同一变量一写一读不同步即 UB；用 atomic 或 mutex。

## 二、计算机组成原理八股

### 2.1 计算机系统概述

**冯·诺依曼结构**
- 存储程序 + 程序控制：指令和数据都以二进制存在同一存储器。
- 五大部件：运算器、控制器、存储器、输入设备、输出设备。
- 与现代区别：现代 CPU 指令缓存/数据缓存分离、多核，但仍是"指令取指-译码-执行"模型。
- 哈佛结构：指令与数据分开存储/总线（DSP、部分 MCU 用）。

**指令执行过程（经典五步骤）**
取指(IF) → 译码(ID) → 执行(EX) → 访存(MEM) → 写回(WB)

### 2.2 数据表示与运算

**原码 / 反码 / 补码（n 位）**

| 类型 | 正数 | 负数 | 特点 |
| --- | --- | --- | --- |
| 原码 | 0 符号位 + 数值 | 1 符号位 + 绝对值 | +0/-0 两个零 |
| 反码 | 同原码 | 符号位不变其余取反 | +0/-0 两个零 |
| 补码 | 同原码 | 反码 + 1 | 唯一零；范围不对称 [-2^(n-1), 2^(n-1)-1] |

- 计算机用补码：加减统一为加法、符号位参与运算、无减法器。
- 溢出判断：两个同号相加结果异号即溢出；或最高位进位与次高位进位不同。
- 位扩展：正数补 0，负数补符号位（算术右移补符号位）。

**IEEE 754 浮点数（必考）**
- float：1 符号 + 8 阶码（偏移 127）+ 23 尾数 → 32 位
- double：1 符号 + 11 阶码（偏移 1023）+ 52 尾数 → 64 位
- 规格化数：`1.xxx × 2^E`，尾数隐含 1；阶码全 1 尾数全 0 = ±∞；阶码全 1 尾数非 0 = NaN；阶码全 0 为次正规数。

```cpp
float f = 0.1f;   // 无法精确表示，二进制无限循环
if (f * 10 == 1.0f) // 不要这么比较
// 用 epsilon: fabs(a-b) < 1e-6
```

- 经典坑：0.1+0.2 != 0.3；大数加小数被吞掉（精度丢失）；浮点比较用阈值。
- 游戏坐标大尺度下抖动：把对象坐标转局部/区块坐标，或用 double 存世界原点。

**位运算技巧（手撕常见）**
- 判断奇偶：`n & 1`
- 2 的幂判断：`n > 0 && (n & (n-1)) == 0`
- 取最低位 1：`n & (-n)`
- 去掉最低位 1：`n & (n-1)`
- 交换：`a ^= b; b ^= a; a ^= b;`
- 快速乘除 2 的幂：`n << k` / `n >> k`（注意右移符号位行为）
- 颜色通道打包/解包（ARGB）常用移位与掩码。

### 2.3 存储系统（重点）

**存储器层次（由快到慢/由小到大/由贵到廉）**
寄存器 → Cache(L1/L2/L3) → 主存(RAM) → 磁盘/SSD
- 上层是下层的缓存，核心思想是局部性：时间局部性（刚访问的数据很快再用）+ 空间局部性（附近数据即将使用）。
- 游戏优化利用空间局部性：紧凑结构体数组（SoA/紧密 AoS）而非指针链（链表的缓存不友好）。

**Cache 基本概念**
- 命中率 = 命中次数 / 总访问次数；平均访问时间 = 命中×Cache 时间 + 未命中×(Cache+主存时间)
- 三种映射：
  - 直接映射：块号 mod 组数 → 冲突率高，硬件简单
  - 全相联：任意放，需全比较 → 命中率高，硬件贵
  - 组相联：折中，每组 n 路（如 4-way），主流 CPU 使用
- 替换算法：LRU（最近最少使用）/ FIFO / 随机
- **写策略**：
  - 写直达（write-through）：同时写 Cache 和主存，简单慢
  - 写回（write-back）：只写 Cache，脏块被替换时才写主存（带 dirty 位），主流
- 未命中种类：强制缺失（首次访问）、容量缺失、冲突缺失。

**虚拟内存与分页**
- 目的：进程间隔离 + 每个进程有连续大地址空间假象 + 按需加载。
- 页式管理：虚拟地址 = 页号 + 页内偏移；页表把虚页映射到物理页帧。
- 缺页异常：访问未在内存页 → OS 从磁盘换入 → 若物理页满按 LRU 换出。
- **TLB**：页表的 Cache（快表），保存最近页表项，命中免去多次访存。
- 页大小常见 4KB（大页 2MB/1GB 可减少 TLB miss，游戏引擎大内存有收益）。
- 段页式：段（逻辑划分）→ 页（物理管理）。

### 2.4 CPU 与流水线

**CPU 组成**
- 控制器（PC、IR、指令译码、时序控制）
- 运算器 ALU（算术逻辑单元 + 寄存器 ACC/MQ/通用寄存器）
- 寄存器堆、程序计数器 PC（指向下一条指令）
- 现代 CPU 内部还有：分支预测器、乱序执行引擎、缓存、SIMD 单元

**流水线**
- 五级：IF-ID-EX-MEM-WB；理想吞吐 = 每周期完成一条。
- **冒险（Hazard）**：
  - 结构冒险：硬件资源冲突（一条指令同时要同一部件）
  - 数据冒险：后一条依赖前一条结果（RAW）→ 转发/旁路（bypass）或停顿（bubble）
  - 控制冒险：分支跳转不知道下一条取谁 → 分支预测 + 延迟槽
- 分支预测失败代价：清空流水线重新取指（深度流水线代价大）。
- SIMD：一条指令处理多个数据（游戏数学库/动画混合大量使用，对应 C# Job/Burst 与 C++ 的 intrinsic）。

**多核缓存一致性（简）**
- MESI 协议：Modified / Exclusive / Shared / Invalid 四态，通过总线嗅探维护 Cache 行一致性。
- 伪共享（false sharing）：不同核改同一缓存行的不同变量 → 频繁同步，性能暴跌；解决：按缓存行（64B）对齐/填充分离热点变量。

### 2.5 总线、中断与 IO

- **总线**：数据总线/地址总线/控制总线；带宽 = 频率 × 位宽。
- **IO 方式**：程序查询（轮询，CPU 忙等）→ 中断（外设通知 CPU）→ **DMA**（外设/控制器直接读写内存，完成才中断一次）→ 通道/IO 处理器。
- 游戏/渲染相关：GPU 通过 DMA/命令缓冲区取数据，减少 CPU-GPU 同步等待。
- **中断处理流程**：保存现场 → 查中断向量 → 执行 ISR → 恢复现场；中断要快、可嵌套（按优先级）。

### 2.6 字节序

- **大端**：高位字节存低地址（网络序）
- **小端**：低位字节存低地址（x86/ARM 主流）
- 跨平台网络/存档协议必须统一字节序；Unity 序列化默认按当前平台，跨端需转。

```cpp
int x = 0x12345678;
// 小端内存: 78 56 34 12；大端: 12 34 56 78
```
