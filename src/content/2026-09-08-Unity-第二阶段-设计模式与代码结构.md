# Unity 第二阶段：设计模式与代码结构学习笔记

这份笔记适合已经会写一些 Unity 功能，但开始感觉代码变乱、功能不好扩展、脚本之间互相依赖太多的阶段。

第二阶段的重点不是背设计模式名字，而是学会：

- 怎么拆类
- 怎么降低耦合
- 怎么让功能更好扩展
- 怎么让 UI、数据、逻辑分开
- 怎么把常见游戏系统写得更清楚

核心目标：

> 从“把功能写出来”，进步到“把系统设计清楚”。

---

## 一、第二阶段应该优先学什么

建议优先掌握这几个最常用的 Unity 编程模式：

1. 观察者模式 / C# 事件
2. 状态机 / 状态模式
3. 对象池
4. 工厂模式
5. 策略模式
6. 单例模式

不建议一开始就学太重的东西，比如：

- 大型资源管理框架
- 网络同步架构
- 完整 MVVM 架构

这些可以后面再学。现在最重要的是把 Unity 常见小系统写清楚。

## 二、观察者模式 / C# 事件

### 适合解决什么问题

观察者模式用于“某个数据变化后，通知其他系统更新”。

Unity 里非常常见：

- 血量变化后，通知血条 UI 刷新
- 金币变化后，通知金币 UI 刷新
- 背包变化后，通知背包 UI 刷新
- 玩家死亡后，通知 GameManager
- 任务进度变化后，通知任务面板

核心思想：

> 数据逻辑只负责发通知，不直接控制 UI 或其他系统。

错误方向：

```csharp
// 不推荐：Health 直接控制 UI，耦合太强
public class Health : MonoBehaviour
{
    public HealthBar healthBar;

    public void TakeDamage(int damage)
    {
        healthBar.UpdateBar();
    }
}
```

更好的方向：

```csharp
using System;
using UnityEngine;

// 生命值组件，只负责生命值逻辑，不直接控制 UI
public class Health : MonoBehaviour
{
    public event Action<int, int> OnHealthChanged;
    public event Action OnDied;

    [SerializeField] private int maxHealth = 100;

    public int CurrentHealth { get; private set; }
    public int MaxHealth => maxHealth;

    private void Awake()
    {
        CurrentHealth = maxHealth;
    }

    public void TakeDamage(int damage)
    {
        if (damage <= 0)
        {
            return;
        }

        CurrentHealth -= damage;
        CurrentHealth = Mathf.Clamp(CurrentHealth, 0, maxHealth);

        // 通知外部生命值发生变化
        OnHealthChanged?.Invoke(CurrentHealth, maxHealth);

        if (CurrentHealth <= 0)
        {
            OnDied?.Invoke();
        }
    }

    public void Heal(int amount)
    {
        if (amount <= 0)
        {
            return;
        }

        CurrentHealth += amount;
        CurrentHealth = Mathf.Clamp(CurrentHealth, 0, maxHealth);

        // 治疗后同样通知外部刷新
        OnHealthChanged?.Invoke(CurrentHealth, maxHealth);
    }
}
```

血条 UI：

```csharp
using UnityEngine;
using UnityEngine.UI;

// 血条 UI，只负责显示生命值，不负责计算伤害
public class HealthBar : MonoBehaviour
{
    [SerializeField] private Health targetHealth;
    [SerializeField] private Image fillImage;

    private void OnEnable()
    {
        targetHealth.OnHealthChanged += Refresh;
    }

    private void OnDisable()
    {
        targetHealth.OnHealthChanged -= Refresh;
    }

    private void Start()
    {
        Refresh(targetHealth.CurrentHealth, targetHealth.MaxHealth);
    }

    private void Refresh(int currentHealth, int maxHealth)
    {
        fillImage.fillAmount = (float)currentHealth / maxHealth;
    }
}
```

攻击者：

```csharp
using UnityEngine;

// 玩家攻击组件，只负责对目标造成伤害
public class PlayerAttack : MonoBehaviour
{
    [SerializeField] private int damage = 10;

    public void Attack(Health target)
    {
        if (target == null)
        {
            return;
        }

        target.TakeDamage(damage);
    }
}
```

GameManager 监听死亡：

```csharp
using UnityEngine;

// 游戏流程管理器，监听玩家死亡事件
public class GameManager : MonoBehaviour
{
    [SerializeField] private Health playerHealth;

    private void OnEnable()
    {
        playerHealth.OnDied += HandlePlayerDied;
    }

    private void OnDisable()
    {
        playerHealth.OnDied -= HandlePlayerDied;
    }

    private void HandlePlayerDied()
    {
        // 这里可以切换失败界面、停止游戏、播放死亡动画等
        Debug.Log("玩家死亡，游戏失败");
    }
}
```

### 练习要求

做一个血量系统：

- `Health` 不引用 `HealthBar`
- `HealthBar` 监听 `Health.OnHealthChanged`
- `GameManager` 监听 `Health.OnDied`
- 攻击逻辑只调用 `TakeDamage`
- 订阅事件写在 `OnEnable`
- 取消订阅写在 `OnDisable`

## 三、状态机 / 状态模式

### 适合解决什么问题

状态机适合处理“一个对象在不同状态下有不同行为”的情况。

常见场景：

- 玩家：待机、移动、攻击、受击、死亡
- 敌人：巡逻、追击、攻击、返回、死亡
- 游戏流程：菜单、游戏中、暂停、结算
- Boss：一阶段、二阶段、狂暴阶段

如果不用状态机，代码很容易变成大量 `if/else`。

```csharp
// 不推荐：状态越来越多后会很难维护
if (isDead)
{
    // 死亡逻辑
}
else if (isAttacking)
{
    // 攻击逻辑
}
else if (isChasing)
{
    // 追击逻辑
}
else
{
    // 待机逻辑
}
```

### 状态接口

```csharp
// 敌人状态接口，每个状态都需要实现这三个方法
public interface IEnemyState
{
    void Enter();
    void Tick();
    void Exit();
}
```

### 状态机

```csharp
// 敌人状态机，负责保存当前状态并切换状态
public class EnemyStateMachine
{
    private IEnemyState currentState;

    public void ChangeState(IEnemyState nextState)
    {
        if (currentState == nextState)
        {
            return;
        }

        currentState?.Exit();
        currentState = nextState;
        currentState?.Enter();
    }

    public void Tick()
    {
        currentState?.Tick();
    }
}
```

### 敌人控制器

```csharp
using UnityEngine;

// 敌人控制器，负责初始化状态并驱动当前状态运行
public class EnemyController : MonoBehaviour
{
    [SerializeField] private Transform player;
    [SerializeField] private float chaseRange = 5f;
    [SerializeField] private float attackRange = 1.5f;
    [SerializeField] private float moveSpeed = 2f;

    private EnemyStateMachine stateMachine;

    public Transform Player => player;
    public float ChaseRange => chaseRange;
    public float AttackRange => attackRange;
    public float MoveSpeed => moveSpeed;

    public EnemyIdleState IdleState { get; private set; }
    public EnemyChaseState ChaseState { get; private set; }
    public EnemyAttackState AttackState { get; private set; }

    private void Awake()
    {
        stateMachine = new EnemyStateMachine();

        // 提前创建状态对象，避免运行时频繁 new
        IdleState = new EnemyIdleState(this, stateMachine);
        ChaseState = new EnemyChaseState(this, stateMachine);
        AttackState = new EnemyAttackState(this, stateMachine);
    }

    private void Start()
    {
        stateMachine.ChangeState(IdleState);
    }

    private void Update()
    {
        stateMachine.Tick();
    }

    public float GetDistanceToPlayer()
    {
        return Vector3.Distance(transform.position, player.position);
    }

    public void MoveToPlayer()
    {
        Vector3 direction = (player.position - transform.position).normalized;
        transform.position += direction * moveSpeed * Time.deltaTime;
    }

    public void AttackPlayer()
    {
        Debug.Log("敌人攻击玩家");
    }
}
```

### 待机状态

```csharp
// 敌人待机状态，负责检查玩家是否进入追击范围
public class EnemyIdleState : IEnemyState
{
    private readonly EnemyController enemy;
    private readonly EnemyStateMachine stateMachine;

    public EnemyIdleState(EnemyController enemy, EnemyStateMachine stateMachine)
    {
        this.enemy = enemy;
        this.stateMachine = stateMachine;
    }

    public void Enter()
    {
        // 这里可以播放待机动画
    }

    public void Tick()
    {
        if (enemy.GetDistanceToPlayer() <= enemy.ChaseRange)
        {
            stateMachine.ChangeState(enemy.ChaseState);
        }
    }

    public void Exit()
    {
        // 离开待机状态时可以清理临时数据
    }
}
```

### 追击状态

```csharp
// 敌人追击状态，负责靠近玩家并判断是否进入攻击范围
public class EnemyChaseState : IEnemyState
{
    private readonly EnemyController enemy;
    private readonly EnemyStateMachine stateMachine;

    public EnemyChaseState(EnemyController enemy, EnemyStateMachine stateMachine)
    {
        this.enemy = enemy;
        this.stateMachine = stateMachine;
    }

    public void Enter()
    {
        // 这里可以播放跑步动画
    }

    public void Tick()
    {
        float distance = enemy.GetDistanceToPlayer();

        if (distance <= enemy.AttackRange)
        {
            stateMachine.ChangeState(enemy.AttackState);
            return;
        }

        if (distance > enemy.ChaseRange)
        {
            stateMachine.ChangeState(enemy.IdleState);
            return;
        }

        enemy.MoveToPlayer();
    }

    public void Exit()
    {
        // 离开追击状态时可以停止移动音效
    }
}
```

### 攻击状态

```csharp
// 敌人攻击状态，负责攻击玩家并判断是否继续追击
public class EnemyAttackState : IEnemyState
{
    private readonly EnemyController enemy;
    private readonly EnemyStateMachine stateMachine;

    private float attackTimer;

    public EnemyAttackState(EnemyController enemy, EnemyStateMachine stateMachine)
    {
        this.enemy = enemy;
        this.stateMachine = stateMachine;
    }

    public void Enter()
    {
        attackTimer = 0f;
        enemy.AttackPlayer();
    }

    public void Tick()
    {
        if (enemy.GetDistanceToPlayer() > enemy.AttackRange)
        {
            stateMachine.ChangeState(enemy.ChaseState);
            return;
        }

        attackTimer += UnityEngine.Time.deltaTime;

        if (attackTimer >= 1f)
        {
            attackTimer = 0f;
            enemy.AttackPlayer();
        }
    }

    public void Exit()
    {
        // 离开攻击状态时可以结束攻击动画
    }
}
```

### 练习要求

做一个敌人 AI：

- Idle：待机
- Chase：追击玩家
- Attack：攻击玩家
- Dead：死亡

然后继续加需求：

- 受击状态
- 冻结状态
- 返回出生点状态
- 远程敌人状态

当你能不用巨大 `if/else` 管理这些状态，就说明状态机开始入门了。

## 四、对象池

### 适合解决什么问题

对象池用于复用高频创建和销毁的对象。

常见场景：

- 子弹
- 特效
- 飘字
- 敌人
- 掉落物
- 音效播放器
- UI 列表项

频繁 `Instantiate` 和 `Destroy` 会产生性能开销，也可能带来 GC 压力。

### 池化对象接口

```csharp
// 可池化对象接口，方便对象在取出和归还时重置状态
public interface IPoolable
{
    void OnSpawn();
    void OnDespawn();
}
```

### 简单对象池

```csharp
using System.Collections.Generic;
using UnityEngine;

// 通用对象池，负责复用 MonoBehaviour 对象
public class ObjectPool<T> where T : MonoBehaviour, IPoolable
{
    private readonly T prefab;
    private readonly Transform parent;
    private readonly Queue<T> availableObjects = new Queue<T>();

    public ObjectPool(T prefab, Transform parent, int initialSize)
    {
        this.prefab = prefab;
        this.parent = parent;

        for (int i = 0; i < initialSize; i++)
        {
            T instance = CreateNewObject();
            instance.gameObject.SetActive(false);
            availableObjects.Enqueue(instance);
        }
    }

    public T Get()
    {
        T instance = availableObjects.Count > 0
            ? availableObjects.Dequeue()
            : CreateNewObject();

        instance.gameObject.SetActive(true);
        instance.OnSpawn();
        return instance;
    }

    public void Release(T instance)
    {
        if (instance == null)
        {
            return;
        }

        instance.OnDespawn();
        instance.gameObject.SetActive(false);
        availableObjects.Enqueue(instance);
    }

    private T CreateNewObject()
    {
        return Object.Instantiate(prefab, parent);
    }
}
```

### 子弹池管理器

```csharp
using UnityEngine;

// 子弹池管理器，负责提供子弹对象
public class BulletPool : MonoBehaviour
{
    [SerializeField] private Bullet bulletPrefab;
    [SerializeField] private int initialSize = 20;

    private ObjectPool<Bullet> pool;

    private void Awake()
    {
        pool = new ObjectPool<Bullet>(bulletPrefab, transform, initialSize);
    }

    public Bullet GetBullet(Vector3 position, Quaternion rotation)
    {
        Bullet bullet = pool.Get();
        bullet.transform.SetPositionAndRotation(position, rotation);
        bullet.SetPool(this);
        return bullet;
    }

    public void ReleaseBullet(Bullet bullet)
    {
        pool.Release(bullet);
    }
}
```

### 子弹对象

```csharp
using UnityEngine;

// 子弹对象，命中或超时后归还对象池
public class Bullet : MonoBehaviour, IPoolable
{
    [SerializeField] private float speed = 10f;
    [SerializeField] private float lifeTime = 3f;

    private BulletPool pool;
    private float lifeTimer;

    public void SetPool(BulletPool bulletPool)
    {
        pool = bulletPool;
    }

    public void OnSpawn()
    {
        lifeTimer = lifeTime;
    }

    public void OnDespawn()
    {
        lifeTimer = 0f;
    }

    private void Update()
    {
        transform.position += transform.forward * speed * Time.deltaTime;

        lifeTimer -= Time.deltaTime;

        if (lifeTimer <= 0f)
        {
            Release();
        }
    }

    private void OnTriggerEnter(Collider other)
    {
        Release();
    }

    private void Release()
    {
        pool.ReleaseBullet(this);
    }
}
```

### 练习要求

做一个子弹对象池：

- 开始时预生成 20 发子弹
- 发射时从池里取
- 命中或超时后归还
- 归还时关闭对象
- 再次取出时重置生命周期

## 五、工厂模式

### 适合解决什么问题

工厂模式用于集中管理对象创建逻辑。

Unity 常见场景：

- 生成敌人
- 生成子弹
- 生成掉落物
- 生成 UI 列表项
- 根据配置创建不同技能

如果到处都写 `Instantiate`，以后创建逻辑变化会很难改。

### 敌人数据

```csharp
using UnityEngine;

// 敌人配置数据，用于描述敌人的基础生成信息
[CreateAssetMenu(menuName = "Game/Enemy Data")]
public class EnemyData : ScriptableObject
{
    public string enemyName;
    public EnemyController prefab;
    public int maxHealth;
    public int attackPower;
}
```

### 敌人工厂

```csharp
using UnityEngine;

// 敌人工厂，集中处理敌人生成逻辑
public class EnemyFactory : MonoBehaviour
{
    public EnemyController CreateEnemy(EnemyData data, Vector3 position, Quaternion rotation)
    {
        if (data == null || data.prefab == null)
        {
            return null;
        }

        EnemyController enemy = Instantiate(data.prefab, position, rotation);

        // 这里可以把 EnemyData 传给敌人，让敌人初始化属性
        enemy.Initialize(data);

        return enemy;
    }
}
```

### 敌人初始化

```csharp
using UnityEngine;

// 敌人控制器，接收配置数据并初始化自身属性
public class EnemyController : MonoBehaviour
{
    private EnemyData data;

    public void Initialize(EnemyData enemyData)
    {
        data = enemyData;

        // 根据配置初始化血量、攻击力、名字等信息
        Debug.Log($"生成敌人：{data.enemyName}");
    }
}
```

### 练习要求

做一个敌人生成器：

- 用 `EnemyData` 配置敌人
- 用 `EnemyFactory` 统一生成敌人
- 不要在很多脚本里到处写 `Instantiate`
- 后续可以把对象池接入工厂

## 六、策略模式

### 适合解决什么问题

策略模式适合处理“同一类行为有多种不同实现”的问题。

Unity 常见场景：

- 不同技能效果：伤害、治疗、护盾、击退
- 不同攻击方式：近战、远程、范围、持续伤害
- 不同移动方式：直线、追踪、抛物线
- 不同掉落规则
- 不同伤害计算公式

如果不用策略模式，代码容易变成很长的 `switch`。

```csharp
// 不推荐：技能越来越多后会很难维护
switch (skillType)
{
    case SkillType.Damage:
        // 伤害逻辑
        break;
    case SkillType.Heal:
        // 治疗逻辑
        break;
    case SkillType.Shield:
        // 护盾逻辑
        break;
}
```

### 技能效果接口

```csharp
using UnityEngine;

// 技能效果接口，所有技能效果都实现 Execute
public interface ISkillEffect
{
    void Execute(GameObject caster, GameObject target);
}
```

### 伤害效果

```csharp
using UnityEngine;

// 伤害技能效果，对目标造成固定伤害
public class DamageEffect : ISkillEffect
{
    private readonly int damage;

    public DamageEffect(int damage)
    {
        this.damage = damage;
    }

    public void Execute(GameObject caster, GameObject target)
    {
        Health health = target.GetComponent<Health>();

        if (health != null)
        {
            health.TakeDamage(damage);
        }
    }
}
```

### 治疗效果

```csharp
using UnityEngine;

// 治疗技能效果，为目标恢复生命值
public class HealEffect : ISkillEffect
{
    private readonly int healAmount;

    public HealEffect(int healAmount)
    {
        this.healAmount = healAmount;
    }

    public void Execute(GameObject caster, GameObject target)
    {
        Health health = target.GetComponent<Health>();

        if (health != null)
        {
            health.Heal(healAmount);
        }
    }
}
```

### 技能释放器

```csharp
using UnityEngine;

// 技能释放器，根据传入的技能效果执行不同逻辑
public class SkillCaster : MonoBehaviour
{
    public void Cast(ISkillEffect effect, GameObject target)
    {
        if (effect == null || target == null)
        {
            return;
        }

        effect.Execute(gameObject, target);
    }
}
```

### 使用示例

```csharp
using UnityEngine;

// 技能测试组件，用于演示策略模式的使用
public class SkillTest : MonoBehaviour
{
    [SerializeField] private SkillCaster caster;
    [SerializeField] private GameObject target;

    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.Alpha1))
        {
            ISkillEffect damageEffect = new DamageEffect(20);
            caster.Cast(damageEffect, target);
        }

        if (Input.GetKeyDown(KeyCode.Alpha2))
        {
            ISkillEffect healEffect = new HealEffect(10);
            caster.Cast(healEffect, target);
        }
    }
}
```

### 练习要求

做一个技能系统：

- 技能释放器不关心具体效果
- 伤害、治疗、击退各写一个效果类
- 新增技能效果时，尽量不修改旧代码
- 不要把所有技能写进一个大 `switch`

## 七、单例模式

### 适合解决什么问题

单例模式适合全局唯一的服务。

常见场景：

- 音频管理器
- 存档管理器
- 场景加载器
- 输入管理器

不建议用于：

- 玩家
- 敌人
- 子弹
- 掉落物
- 普通 UI 面板

不要为了访问方便就全部写成单例。

### 音频管理器示例

```csharp
using UnityEngine;

// 音频管理器，全局只保留一个实例
public class AudioManager : MonoBehaviour
{
    public static AudioManager Instance { get; private set; }

    [SerializeField] private AudioSource sfxSource;

    private void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }

        Instance = this;
        DontDestroyOnLoad(gameObject);
    }

    public void PlaySfx(AudioClip clip)
    {
        if (clip == null)
        {
            return;
        }

        sfxSource.PlayOneShot(clip);
    }
}
```

使用：

```csharp
// 播放一次音效
AudioManager.Instance.PlaySfx(hitSound);
```

### 单例使用原则

可以用单例的情况：

- 全局唯一
- 生命周期较长
- 很多系统确实需要访问
- 更像服务，而不是具体游戏对象

应该避免的情况：

- 只是为了少拖引用
- 每个系统都互相 `Manager.Instance`
- 单例里塞了太多职责
- 所有功能都依赖 `GameManager`

## 十、判断自己有没有掌握

不要用“我看了几个教程”判断自己。

应该用这些问题判断：

1. 我能不能解释这个模式解决了什么问题？
2. 我能不能说出不用它时代码会怎么变糟？
3. 我能不能在 Unity 里独立写一个例子？
4. 我能不能加一个新需求，而不大面积修改旧代码？
5. 我能不能判断什么时候不该用这个模式？

如果这五点能做到，才算真的掌握。

---

## 十一、最重要的提醒

设计模式不是越多越好。

好的代码不是“用了很多模式”，而是：

- 职责清楚
- 改起来容易
- 依赖关系简单
- 新需求不会牵一发动全身
- 出 Bug 时能快速定位

如果一个功能 30 行代码已经很清楚，就不要强行拆成 8 个类。

第二阶段真正要练的是：

> 先把功能写出来，再观察哪里难改，最后用合适的结构重构它。
