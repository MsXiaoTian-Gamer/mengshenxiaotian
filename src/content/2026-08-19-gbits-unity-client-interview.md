# 吉比特 Unity 客户端面试经历：一场暴露短板的复盘

**吉比特 Unity 客户端 · 一面经历**

> 投了吉比特的 Unity 客户端岗位，面试整体氛围还算友好，但这场面试把我知识体系里的窟窿照得明明白白——"用过"和"懂"之间的距离，面试官一问就现形。趁还记得，把过程和技术点完整复盘一遍，给准备客户端方向的同学做个参考。

## 一、面试概况

| 项目 | 内容 |
|------|------|
| 面试公司 | 吉比特 |
| 意向岗位 | Unity 客户端开发 |
| 考察方向 | 引擎基础、UGUI、渲染与 Shader、数据结构、架构与设计模式、网络与异步编程 |
| 面试结论 | 基础知识暴露较多缺口，项目广度尚可，深度不足 |

## 二、面试过程

### 1. 引擎基础与 UGUI：第一波就有点懵

面试从引擎基础开始。第一个问题就被问住了——**Mask 和 Rect Mask 组件的区别**。老实说，这两个组件我平时都没实际用过，直接坦白不了解，场面一度很尴尬。

接着问 **TextMeshPro 文本控件**。这个我倒是知道是 Unity 自研的高性能文本控件，但面试官追问"为什么高性能"时，我讲不出底层原理，只能说"它比普通 Text 好"这种空话。

**Timeline 动画管道**也只答了表面——我知道它能做路径编排、剪辑动画，但被问到管道核心实现时，只能摇头。

最后问 **UGUI 运行时 API**，我坦承不熟，无限循环列表这种实操题也没做过。

> 这一趴的教训很直接：平时用组件只停留在"会用"，面试官一追问"为什么高性能、底层怎么跑"就露怯。

### 2. 渲染管线与 Shader：有成果，但含金量不足

渲染这块问得比较细。

**URP 渲染管线**我还算能说几句：能替代 Built-in、支持多平台跨端、移动端有 SRP 合批。但被问到管线底层修改逻辑时，就答不上来了。

**Shader 溶解效果**我做过——但那是跟着课程敲出来的，不是自己独立实现的，面试官一听就明白含金量。

**顶点/片元着色器**我还能对应到渲染管线里的环节，算是个基础分。

但 **Shader 状态设置**完全没了解过：混合模式、Z 测试开关这些，我一脸茫然。

> 有 Shader 练习成果确实是加分项，但"跟课敲的"和"自己能写"是两码事，状态设置这类基础必须补。

### 3. 数据结构：手写能力是硬伤

数据结构这块直接暴露了练习量不足。

手写数据结构只写过**列表**，树和图都没动手实现过。**二叉树**只停留在了解结构，虽然用 C 语言写过基础实现，但被追问时就显得单薄。**红黑树**只听说过概念，实现完全没掌握。

> 客户端开发同样考数据结构，容器用惯了，手写能力就废了，这个真得日常练。

### 4. 架构与设计模式：全场少数的加分模块

架构这块是我整场面试相对有底气的部分。

**MVC 分层架构**只记得"解耦"这个作用，三层定义没记全，答得模模糊糊。

**自研 Unity 六层架构**能说出各层的基础职责，这个项目里确实用过。

**UI 管理器**只有接口实现，没有基类抽象，被追问时自己都觉得站不住。

但**工厂/策略模式**我用武器系统举例讲得不错：新增武器只需注册策略接口就能解耦。面试官明显对这个真实落地场景感兴趣。

> 设计模式有真实项目落地场景，是整场面试少数的加分模块。面试官要的就是这种"能落地"的答案，而不是背概念。

### 5. 网络与异步：会调 API 不等于懂网络

**HTTP + JSON 后端对接**是我做得比较完整的一块：登录 → 请求 → 校验 → 解析 JSON → 生成日程数据，流程能讲清楚。

但 **TCP / UDP** 只知基础区别，没有实操过网络通信代码，一问细节就露怯。

**Unitask / async-await** 运行逻辑表述有偏差，讲不清 async/await 的核心作用，概念是模糊的。

> 会调 API 不等于懂网络，异步编程概念模糊是硬伤，这块得系统补。

### 6. 动画与场景

**Blend Tree** 只知融合作用，被问到重叠部分的差值计算逻辑时答不上来。

**Cinemachine 自由观察**是我自定义实现的，没有用 Unity 自带的扩展机制，这个倒是能讲清楚自己的实现思路。

### 7. 认真准备的反而没被问到

有意思的是，面试前我认真准备了 **AI 行为树** 和 **状态机** 的内容，结果整场面试完全没被问到。反而是一些我以为"用用就会"的细节被追着问到底。

> 准备方向永远猜不准面试官的考察点，与其押题，不如把每个用过的组件都往"底层原理"多挖一层。

## 三、面试官交流印象

面试官提到一个观点：AI 辅助编程可以和自身学习形成正向循环。

我的观点是先能独立敲出代码再借助 AI 工具——这个观点本身没问题，但面试官更看重"如何用 AI 放大学习效率"。事后复盘，我在交流中暴露了对 AI 辅助学习路径的思考不够深，没有给出更有建设性的回答。

## 四、经验教训

1. **"用过"不等于"懂"**：本次面试几乎每个失分点都是"只停留在使用层"——TMP 高性能说不出原因、Timeline 说不清管道、Blend Tree 讲不了差值计算。面试考的是原理，不是操作。
2. **八股基础不能裸奔**：MVC 三层定义、红黑树、Mask/RectMask 区别属于高频低成本的送分题，丢分最可惜。
3. **手写能力要日常练**：数据结构手写、无限循环列表这类实操题，不练就是不会，临时抱佛脚无效。
4. **项目深度比数量重要**：项目经历丰富是优势，但每个项目都要能讲清"难点 → 方案 → 为什么这么设计"，STAR 逻辑必须完整。
5. **有真实落地场景的答案是最大亮点**：工厂/策略模式能用武器系统举例，说明项目里确实用过；面试官要的就是这种"能落地"的答案，而不是背概念。
